# CHAPTER 1. PROJECT OVERVIEW

## 1.1. Rationale for Choosing the Topic
In today's expanding fragrance market, consumer demand to experience and test perfumes directly before purchasing full-sized bottles is increasingly high. However, traditional in-store perfume sampling methods face several major limitations:
- **Labor Constraints:** Requires high labor costs and heavily relies on physical retail stores staffed with consultants.
- **Sample Wastage:** Perfume brands struggle to accurately track actual sample consumption, leading to potential inventory loss or wasted testers.
- **Lack of Operational Insights:** Lack of precise operational data regarding customer interest levels for specific fragrance notes across different sampling locations.
- **Manual Maintenance:** Manual checking of perfume container levels and machine operating status is time-consuming and risks service interruptions.

Recent advancements in Internet of Things (IoT) technology, cashless payment systems (QR Code), and cloud-based management platforms present an innovative solution for automated perfume sampling. Recognizing this opportunity, our team selected the project topic: **"ScentStation: A Multi-Brand IoT Perfume Experience and Management Platform"**.

ScentStation delivers a comprehensive solution for both consumers and management teams:
- **For Customers:** Customers can interact with a kiosk, browse and select a fragrance, complete QR-code payment, and receive one controlled spray after the backend confirms successful payment.
- **For Brands & Operations:** ScentStation provides a centralized management platform built on a multi-tenant architecture. Each brand operates within an isolated workspace to manage product catalogs, monitor kiosk status, track estimated remaining perfume quantities, handle technical incidents, and analyze operational performance.

Through this Java Programming course project, our team aims to apply core software engineering concepts, including Multi-Tenant Architecture, RESTful API development with Java 21 & Spring Boot, relational database management with PostgreSQL, real-time IoT messaging via MQTT, and modern front-end development using Next.js & React. This project provides a valuable opportunity for team members to enhance teamwork skills, coordinate feature development, and gain hands-on experience in the software development lifecycle from architectural design to system implementation.

## 1.2. Project Objectives

### 1.2.1. General Objective
The primary objective of the ScentStation project is to develop a centralized web-based management platform integrated with an automated multi-brand IoT perfume sampling kiosk system. The platform addresses two primary functional domains:
- **Customer Side (Kiosk):** Enables customers to browse fragrance catalogs, view product details, complete QR code payments, and receive automated trial sprays.
- **Administration & Operations Side:** Provides role-based administrative tools for perfume brands and operations teams to manage product catalogs, sampling kiosks, compartments (slots), inventory levels, transaction histories, maintenance workflows, and operational analytics.

Technologically, the system utilizes Java 21 and Spring Boot for the backend; Next.js, React, and TypeScript for the frontend; PostgreSQL for data persistence; and MQTT for IoT device communication. The platform is designed around a multi-tenant architecture paired with Role-Based Access Control (RBAC) to ensure strict data isolation across participating brands.

### 1.2.2. Specific Objectives

#### a) Authentication, Authorization, and User Management
- Develop authentication, user account management, and Role-Based Access Control (RBAC) functionality. Key system roles include Platform Super Administrator, Brand Administrator, Operations Manager, Technician, Inventory Staff, and Customer/Kiosk User.
- Enforce tenant isolation and access control policies strictly at the backend level.
- Support account activation, locking, session management, and log login attempts and permission updates.

#### b) Brand and Perfume Catalog Management
- Manage brand profiles, logos, descriptions, and kiosk display content.
- Manage perfume catalogs: product names, descriptions, fragrance notes, display images, price per spray, and business availability status.
- Ensure multi-tenant data isolation, preventing unauthorized cross-brand data access.

#### c) Sampling Kiosk and Slot Management
- Register sampling kiosks using unique serial numbers, assigning machines to specific brands and physical locations.
- Configure perfume slots on each kiosk (each prototype machine supports at least 4 independently controlled slots).
- Monitor device connection status (Online/Offline), operating state (Active, Paused, Under Maintenance), and slot inventory status.
- Maintain installation, relocation, configuration change, and maintenance history for every machine.

#### d) Ordering Process and QR Payment Workflow
- Build a seamless ordering workflow for customers to select fragrances, review pricing, and generate orders at the kiosk.
- Generate dynamic QR payment codes and manage transaction states (Pending, Successful, Failed, Expired, Refunded).
- Verify payment status on the backend before issuing dispensing commands to the kiosk. Handle operational edge cases (e.g., successful payment with failed dispensing).

#### e) MQTT Communication and Dispensing Management
- Utilize MQTT protocol for real-time bi-directional messaging between the backend and kiosk hardware.
- Assign each dispensing command a unique identifier (UUID) linked to its order, and implement command validation and duplicate-processing protection to reduce the risk of duplicate dispensing.
- Receive execution responses from kiosks, update order statuses, and log hardware failure codes.

#### f) Inventory Tracking and Level Estimation
- Manage inventory batches, perfume bottles/cartridges, quantities, receipt dates, and expiration dates.
- Assign bottles to specific machine slots and record initial liquid volumes.
- Estimate remaining perfume levels based on successful spray counts combined with hardware sensor readings (where available).
- Trigger automated alerts when perfume levels drop below low-stock thresholds, when slots become empty, or when abnormal consumption (leakage) is detected.

#### g) Maintenance Management and Incident Handling
- Develop an end-to-end maintenance ticket workflow from fault detection and technician assignment to repair completion.
- Allow machines to be placed into Maintenance Mode to prevent new customer orders during critical hardware faults.
- Enable technicians to execute maintenance checklists, conduct test sprays, and record repair results before returning machines to active service.

#### h) System Audit Trail and Traceability
- Automatically record critical system actions: user logins, price updates, inventory adjustments, device control commands, maintenance activities, and permission changes.
- Store complete audit metadata: Actor, Tenant, Action, Target Object, Timestamp, and Before/After values.
- Prevent regular users from modifying or deleting audit records. Support searching and filtering logs by time, user, machine, or event type.

#### i) Statistics and Operational Reporting
- Provide a visual dashboard showing key metrics: machine status breakdown, transaction volume, revenue, dispensing success/failure rates, top-performing fragrances, and stock alerts.
- Support report filtering by date range, brand, location, and enable data export to CSV/Excel formats.

#### j) Security, Reliability, and Data Integrity
- Implement JWT for stateless request authentication, BCrypt for password hashing, and HMAC-SHA256 for signing device control commands.
- Enforce key business constraints: a successfully paid order must result in no more than one successful spray, and each slot can contain at most one active bottle or cartridge at a time.

## 1.3. Project Scope

### 1.3.1. In-Scope Features
- Account management, RBAC access control, and multi-tenant brand data isolation.
- Perfume catalog management, brand profiles, pricing, and availability controls.
- Customer kiosk interface: Fragrance browsing, product details view, order creation, QR payment, and automated dispensing.
- Sampling kiosk and slot management: Connectivity monitoring, configuration settings, and remote enable/disable controls.
- IoT messaging via MQTT: Telemetry collection, secure command dispatching, and hardware execution feedback.
- Perfume inventory management: Bottle/cartridge tracking, consumption estimation, low-stock alerts, and replacement logging.
- Maintenance management: Fault ticket creation, technician assignment, checklists, and repair history tracking.
- System Audit Log: Comprehensive activity logging for security investigation and operational traceability.
- Operational reports and analytics: Visual dashboard for revenue, spray counts, kiosk status, and CSV report exports.

### 1.3.2. Project Deliverables
- A functional prototype perfume sampling kiosk with at least 4 independently controlled fragrance slots.
- A touch-screen kiosk user interface application for customers.
- Backend API platform, PostgreSQL database schema, and authentication service.
- A web-based administration portal supporting multi-brand management.
- Full project source code, installation/operation documentation, and test execution reports.

### 1.3.3. Out-of-Scope Items
- Developing industrial-scale perfume production or packaging machinery.
- Building a full e-commerce retail portal for selling and shipping full-sized perfume bottles.
- Developing a standalone mobile application (iOS/Android) for end customers.
- Direct integration with all commercial banks/e-wallets (the project implements/simulates standard QR payment workflows).
- Commercial-scale nationwide deployment.

### 1.3.4. Assumptions and Constraints
- Sampling kiosks must maintain internet connectivity with the backend to verify payments before dispensing.
- Each prototype machine features at least 4 independently operated perfume slots.
- Perfume dispensing is executed only when safety constraints are met: cabinet door closed, sufficient perfume available, and machine not under maintenance.

## 1.4. Target Users

The ScentStation platform is designed for several distinct user groups, each assigned specific roles and operational responsibilities:

1. **Customers (Customer / Kiosk User):** End customers who experience fragrances at the kiosk. They browse fragrance catalogs, view product details, select items, make payments via QR code, and receive controlled trial sprays.
2. **Platform Super Administrator:** Platform-wide administrators responsible for managing all brand tenants, configuring global system parameters, monitoring all registered kiosks, reviewing system-wide analytics, and auditing system logs.
3. **Brand Administrator:** Brand-level administrators managing business operations for a specific perfume brand. Responsibilities include updating brand profiles, managing perfume product catalogs, setting prices per spray, managing brand employee accounts, and analyzing brand sales reports.
4. **Operations Manager:** Operations personnel monitoring daily kiosk activities and machine health. They track machine connectivity (Online/Offline), handle transaction anomalies, and create/assign maintenance tickets to technicians.
5. **Technician:** Technical staff responsible for inspecting, maintaining, and repairing sampling kiosks. Technicians handle assigned maintenance tickets, place machines in maintenance mode, perform diagnostic test sprays, and record repair results.
6. **Inventory Staff:** Warehouse and inventory personnel responsible for monitoring perfume levels across kiosk slots, executing bottle/cartridge replacements, recording refill operations, and updating inventory records.

## 1.5. Technologies Used

The ScentStation system is built upon a 3-tier architecture comprising: Presentation Tier (Frontend), Business Logic Tier (Backend), and Device Tier (IoT Sampling Kiosks). Inter-tier communication is achieved via RESTful APIs and the MQTT messaging protocol.

### 1.5.1. Backend Technologies
| Technology / Tool | Version | Role in System |
| :--- | :--- | :--- |
| **Java (Temurin JDK)** | 21 LTS | Primary programming language for Backend development |
| **Spring Boot** | 3.3.5 | Application framework and RESTful API provider |
| **Spring Security** | 6.x | Authentication and Role-Based Access Control (RBAC) |
| **Spring Data JPA / Hibernate** | 6.x | Object-Relational Mapping (ORM) and database persistence |
| **Maven** | 3.9+ | Dependency management and project build tool |

*Java 21 and Spring Boot are mandatory core technologies for this course. Spring Boot provides built-in Dependency Injection, Transaction Management, and Security mechanisms, allowing the team to focus on business logic implementation. JDK 21 LTS ensures high performance and long-term stability.*

### 1.5.2. Database Management
| Technology / Tool | Version | Role in System |
| :--- | :--- | :--- |
| **PostgreSQL** | 16 | Primary relational database management system |
| **Flyway** | 10.x | Database schema version control and migration tool |

*PostgreSQL supports partial unique indexes, which can be used to enforce database-level constraints such as allowing no more than one active dispensing command per order and no more than one active bottle assignment per slot. Flyway allows seamless database schema synchronization across all team members.*
